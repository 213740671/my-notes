# C++ STL 核心容器与适配器笔记

## 1. 核心数据结构对比

在 C++ STL 中，根据逻辑行为和内存布局，我们可以将这三者分为 **容器 (Containers)** 和 **适配器 (Adapters)**。

| 特性 | std::vector (动态数组) | std::stack (栈) | std::queue (队列) |
| :--- | :--- | :--- | :--- |
| **本质** | 连续内存的动态数组 | 容器适配器（后进先出 LIFO） | 容器适配器（先进先出 FIFO） |
| **访问能力** | **随机访问**：可通过 `vec[i]` 在 @@MATH_BLOCK_0@@ 时间访问任意元素 | **受限访问**：仅能访问栈顶 `top()` | **受限访问**：仅能访问队首 `front()` 和队尾 `back()` |
| **迭代器** | 支持迭代器，可以遍历 | **不支持**迭代器 | **不支持**迭代器 |
| **插入/删除** | 末尾极快，中间较慢（需移动元素） | 仅限栈顶 `push()` / `pop()` | 队尾进 `push()`，队首出 `pop()` |
| **常见场景** | 存储数据、随机查询、代替原生数组 | 递归模拟、撤销操作（Undo）、括号匹配 | 任务调度、消息队列、广度优先搜索 (BFS) |

---

## 2. 深入理解：std::vector vs. std::stack

虽然 `vector` 可以通过 `push_back` 和 `pop_back` 实现栈的功能，但两者在设计哲学上有本质不同：

* **逻辑封装：** `stack` 故意“阉割”了随机访问和中间插入的功能，以保证 **LIFO** 的逻辑安全性。
* **底层实现：** * `vector` 自己管理一块连续内存。
    * `stack` 是一个壳，默认基于 `std::deque`（双端队列）实现，也可以手动指定基于 `vector` 实现：`std::stack<int, std::vector<int>> s;`。

## 3. std::vector 核心操作指南

### A. 修改元素 (Modification)
由于 `vector` 内存连续，修改操作非常高效。
* **下标法：** `vec[i] = value;` —— 速度最快，不检查越界。
* **at()法：** `vec.at(i) = value;` —— 会进行越界检查，若越界会抛出 `std::out_of_range` 异常。

### B. 中间插入元素 (Insertion)
插入操作需要使用 **迭代器 (Iterator)**。
* **语法：** `vec.insert(pos, value);`
* **性能：** 时间复杂度为 @@MATH_BLOCK_1@@。
* **底层逻辑：**
    1.  **腾挪：** 插入点之后的所有元素必须依次向后移动一位。
    2.  **扩容：** 如果当前 `capacity` 不足，会触发重新分配内存，导致所有现有迭代器失效。

### C. 代码示例
```cpp
#include <vector>
#include <iostream>

int main() {
    std::vector<int> v = {1, 2, 4, 5};

    // 1. 修改
    v[1] = 20; // {1, 20, 4, 5}

    // 2. 中间插入 (在索引 2 的位置插入 3)
    v.insert(v.begin() + 2, 3); // {1, 20, 3, 4, 5}

    // 3. 批量插入
    std::vector<int> extra = {100, 200};
    v.insert(v.end(), extra.begin(), extra.end()); // 末尾追加
}
```

## 4. 总结与建议

* **追求性能与灵活：** 首选 `vector`。
* **追求逻辑严谨（后进先出）：** 使用 `stack`，防止误操作中间数据。
* **频繁中间插入/删除：** 如果 @@MATH_BLOCK_2@@ 的移动代价过大，请考虑使用 `std::list` (双向链表)，其插入复杂度为 @@MATH_BLOCK_3@@。
