### 1\. `fputc` 和 `USART1` 的关系：重定向 (Redirection)

在 C 语言中，我们习惯用 `printf` 来打印信息。

  * **`printf` 的工作原理：** 它负责把数字、变量格式化成字符串，但它**不知道**怎么把这些字符发送到电脑屏幕上。它只负责“加工”数据。
  * **`fputc` 的作用：** `printf` 在加工好每一个字符后，会调用底层的 `fputc` 函数，告诉它：“把这个字符发出去”。

**在 PC 上：** `fputc` 默认把字符发给显示器驱动。
**在 STM32 上：** 并没有默认的“显示器”。我们需要**重写** `fputc` 函数，在里面填入让 `USART1` 发送数据的代码。

**流程如下：**

> 代码调用 `printf("Hello")` -\> `printf` 拆解字符 -\> 逐个调用 `fputc('H')`, `fputc('e')...` -\> **你重写的 `fputc`** -\> 调用 STM32 硬件串口 (USART1) -\> 通过 TX 引脚发送电平信号 -\> 电脑串口助手接收显示。

这就是所谓的\*\*“串口重定向”\*\*。

### 2\. 为什么必须要开启 `USART1`？

这里有两个层面的原因：

#### A. 硬件配置层面 (CubeMX 的作用)

就像你的截图里做的这样，你必须在 STM32CubeMX 里把 USART1 的模式选为 **Asynchronous (异步)**，原因如下：

1.  **时钟：** 芯片默认是为了省电关闭外设时钟的。开启后，芯片才会给 USART1 供电和提供时钟信号。
2.  **引脚复用：** 也就是你右边图里的 `PA9` (TX) 和 `PA10` (RX)。如果不开启，这两个脚就是普通的 GPIO，无法发送串口波形。
3.  **波特率设置：** 你必须配置波特率（如 115200），硬件才知道发送数据的速度，电脑才能正确解码。

#### B. 软件代码层面

虽然不一定非要是 `USART1`（你也可以用 USART2、3 等），但通常**约定俗成**使用 `USART1` 作为调试打印口 (`printf` 输出口)，原因有二：

1.  **默认连接：** 在很多 STM32 开发板上，USART1 是默认连接到 USB 转串口芯片（或 ST-Link 的虚拟串口）上的，接上 USB 线就能在电脑看数据。
2.  **代码匹配：** 如果你在重写 `fputc` 时，代码里写的是 `&huart1`（对应 USART1），那么你在 CubeMX 里就必须开启 USART1。如果你代码写发给串口 1，但硬件开了串口 2，那是发不出去的。

### 3\. 如何实现？(代码示例)

配置好 CubeMX 并生成代码后，你需要在 `main.c` 或 `usart.c` 中添加以下代码（通常放在 `/* USER CODE BEGIN 0 */` 区域）：

```c
#include <stdio.h>

// 重写 fputc 函数
int fputc(int ch, FILE *f)
{
    // 这里的 &huart1 决定了 printf 输出到哪个串口
    // 如果你想用串口2，就改成 &huart2
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 0xFFFF); 
    return ch;
}
```

### 4\. 特别注意 (Keil 环境)

如果你使用的是 **Keil MDK** 开发环境，光写上面的代码可能程序会卡死。你还需要做一步操作：

  * **勾选 "Use MicroLIB"**：
      * 点击魔术棒图标 (Options for Target) -\> Target 选项卡 -\> 勾选 **Use MicroLIB**。
      * *原因：标准 C 库比较庞大且依赖操作系统，MicroLIB 是 Keil 专门为嵌入式优化的精简库，支持直接使用 printf。*

**总结：**
开启 USART1 是为了准备好硬件通道，重写 `fputc` 是为了告诉编译器“把 `printf` 的数据扔到这个通道里去”。两者结合，你才能在电脑屏幕上看到 STM32 打印的信息。
