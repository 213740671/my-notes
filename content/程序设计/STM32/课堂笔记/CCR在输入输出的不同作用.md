# STM32 定时器：CCR (捕获/比较寄存器) 的双重角色

## 1. 核心区别总结

CCR 是同一个物理寄存器，但在不同模式下，**数据流向**和**功能**完全相反。

| 特性 | 输出比较 (PWM) | 输入捕获 (测频率/脉宽) |
| :--- | :--- | :--- |
| **角色定义** | **阈值 / 目标值** | **快照 / 容器** |
| **核心功能** | 决定何时翻转电平 (控制占空比) | 记录信号发生的准确时刻 (时间戳) |
| **数据流向** | **软件 (CPU) $\rightarrow$ CCR** | **硬件 (CNT) $\rightarrow$ CCR** |
| **谁来写值** | **你** (代码中写入) | **硬件** (自动从 CNT 搬运) |
| **谁来读值** | 硬件 (比较器电路) | **你** (在中断中读取) |

---

## 2. 详细工作原理

### (1) 输出比较模式 (PWM) —— CCR 是“考官”
* **场景**：产生 PWM 波形，控制电机速度或 LED 亮度。
* **工作流程**：
    1.  CNT 计数器不断自增 (0 $\rightarrow$ ARR)。
    2.  硬件实时比较 CNT 与 CCR 的值：
        * 当 `CNT < CCR`：输出有效电平 (如高电平)。
        * 当 `CNT >= CCR`：输出无效电平 (如低电平)。
* **结论**：CCR 的值决定了**占空比**。如果没有 CCR，硬件不知道何时翻转电平。

### (2) 输入捕获模式 (Input Capture) —— CCR 是“照相机”
* **场景**：测量外部方波的频率或周期。
* **工作流程**：
    1.  CNT 计数器一直在跑。
    2.  **外部信号 (上升沿)** 到达引脚。
    3.  硬件触发“快门”，瞬间**锁存**当前 CNT 的值，并将其**自动复制**到 CCR 中。
    4.  触发捕获中断，通知 CPU。
* **结论**：CCR 保存的是**事件发生的准确时间戳**。你需要读取 CCR 来计算两次边沿之间的时间差。

## 3. 关键疑问：为什么输入捕获必须用 CCR？

**Q: 既然 CNT 已经在计数了，为什么不能在中断里直接读取 CNT 的值？**

**A: 为了消除软件延迟，保证精度。**

1.  **中断延迟**：从信号触发到 CPU 真正跳进中断函数执行代码，中间有几十个时钟周期的延迟 (压栈、流水线清空等)。
2.  **CNT 不等人**：在这段延迟时间内，CNT 还在高速增加。
3.  **结果**：如果在中断里直接读 CNT，读到的值比信号实际发生的时间**滞后**了，导致测量不准。

**CCR 的作用 (硬件锁存)**：
信号到来的**纳秒级**瞬间，硬件直接把 CNT 存入 CCR。无论 CPU 晚多久才来读 CCR，里面的值永远是**信号发生那一刻**的真实值。
